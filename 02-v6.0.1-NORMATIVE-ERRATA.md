# S-Class v6.0.1 - Normative Errata

This document is a **change log for the corrections already folded into the active v6.0.1 specification**. It is not a second semantic authority. The active specification is authoritative.

## ERR-001 - Canonical event/commit binding

**Applied in active spec:** §2.2 CanonicalCommit prose and §12.1 event model.

Add to `CanonicalEvent`:

```python
commit_id: str
```

Add:

```python
@dataclass(frozen=True)
class CommitRecord:
    commit_id: str
    workspace_id: str
    command_id: Optional[str]
    participant_ids: tuple[str, ...]
    expected_versions: FrozenMap
    causal_frontier_digest: Digest
    state: CommitState
    recovery_epoch: int
    integrity_digest: Digest
```

Rules:

1. A consequential transition allocates exactly one `commit_id`.
2. Every participating canonical event carries that id.
3. `CommitRecord.state == COMMITTED` is the only authoritative visibility state.
4. A participant with a missing/non-COMMITTED record is quarantined.
5. Recovery can only advance one claimed commit epoch.

## ERR-002 - Direct authority conjunction

**Applied in active spec:** §8.1 claim that the security gate relies on `EffectScope.intersect` as the primary security primitive.

The normative security predicate is:

```python
all(authorized(request, scope) == AUTHORIZED for scope in
    (attested_scope, policy_scope, lease_scope))
```

A computed `EffectScope` meet is an optimization only. It is never authoritative unless the biconditional property test passes.

## ERR-003 - Action-bound capability

**Applied in active spec:** §8.2 / §8.3 capability binding.

Authorization must verify:

```text
request.action_type == selected_capability.action
capability.valid_from <= trusted_now < capability.valid_until
```

`action_type` is covered by `authorization_binding_digest` and `envelope_digest`.

## ERR-004 - Path canonicalization

**Applied in active spec:** `_canonical_rel` and all path-prefix comparisons.

Canonical relative paths:

- root is exactly `.`
- non-root path has no empty component
- no component may be `.` or `..`
- no trailing slash
- no backslash, NUL, colon, or control/format character
- NFC only
- rule prefixes use the same validation
- comparisons occur only after normalization

## ERR-005 - Budget/numeric domains

All bounded numeric fields must reject invalid values at construction and ingress.

For counters, byte counts, timestamps and resource quantities:

```text
0 <= value <= 2^63 - 1
```

Special domains:

```text
confidence_bp: 0..10000
TCP/UDP port: 1..65535
```

Signed and checked arithmetic is mandatory for reserve/settle/release.

## ERR-006 - Evidence binding

Extend `SignedEvidencePayload` with:

```python
evidence_kind: EvidenceKind

observation_id: str
target_snapshot_digest: Digest
```

The signature covers all payload fields. Any change to these fields invalidates the receipt.

One receipt counts only for the obligation and requirement key named in its signed payload.

## ERR-008 - Execution generation

`WorkResult` must include:

```python
execution_generation: int
execution_attempt_id: str
target_snapshot_digest: Digest
state_binding_digest: Digest
governing_budget_lineage_id: str
objective_revision: str
workgraph_revision: str
```

Reducer rule:

```text
result.generation == current_generation
AND
result.attempt is still authoritative
AND
all bindings match current state
```

Otherwise store it as historical evidence only and return `DENIED_STALE_GENERATION` to the mutation path.

## ERR-009 - Process and external rule uniqueness

Reject duplicate canonical keys at policy/attestation ingress.

Process key:

```text
(executable_digest, argv_digest)
```

External-effect key:

```text
(target_system, effect_kind)
```

No authorization function may use `next(...)` / first-match selection for security-relevant duplicate-capable rules.

## ERR-010 - Network resolution / redirects

Remove requester authority over DNS resolution.

The boundary performs resolution, records the actual result, and connects only to addresses authorized under the current policy.

Redirect behavior:

- `allow_redirects=False`: adapter must reject/disable redirects.
- `allow_redirects=True`: every redirect destination is re-evaluated against the same authority stack.
- every redirect is captured in the observation lineage.

## ERR-012 - Evidence composition semantics

For a contract with mandatory rows `M` and non-mandatory alternatives `N`:

```text
ALL      => every active row in M ∪ N is satisfied
ANY_OF   => every row in M is satisfied AND >=1 row in N is satisfied
K_OF_N   => every row in M is satisfied AND >=k distinct rows in N are satisfied
```

Validation:

```text
min_receipts >= 1
1 <= k <= |N|
```

A row is satisfied iff it has at least `min_receipts` distinct signature-valid PASS receipts that are admissible under its exact requirement binding.

## ERR-013 - Approval validator

Delete the duplicate validator. Keep only `validate_approval_set()`.

Required quorum is supplied by trusted policy, not by `ApprovalSet.required_principals`.

Validate:

- signature
- kind
- target
- workspace
- policy revision
- scope digest
- validity window
- principal role
- principal identity proof
- distinct-human rule when required
- requester != approver when required

Return typed failure reasons; do not silently skip malformed approvals.

## ERR-014 - Policy floor

The baseline policy floor is shipped as a frozen fixture. The loader:

1. reads fixture bytes
2. computes its canonical digest
3. verifies the issuer signature
4. compares the recomputed digest with the recorded digest
5. only then compares candidate policy against the floor

A caller-supplied `floor_digest` is never accepted as proof.

## ERR-015 - Release evaluation

Remove the free-form `ReleaseFacts` authority input from the public release gate.

Replace with:

```python
@dataclass(frozen=True)
class ReleaseEvaluation:
    release_id: str
    acceptance_snapshot_digest: Digest
    derived_obligation_results: FrozenMap
    derived_assessment_results: FrozenMap
    derived_waiver_results: FrozenMap
    artifact_provenance_digest: Digest
    evaluation_digest: Digest
    verdict: ReleaseVerdict
    evaluated_at: UtcInstant
```

`ReleaseEvaluation` is derived only from canonical, validated state. Recompute before release. Any mismatch between stored evaluation and derived facts -> `NOT_EVALUABLE`.

## ERR-016 - Canonical immutable values

Every canonical dataclass must be created through a single enforced construction decorator/factory that recursively freezes nested values. Direct use of mutable lists/dicts/sets/bytearrays in canonical objects is forbidden.

CI rule:

```text
canonical registry entry -> canonical_dataclass decorator required
```

## ERR-017 - c1 domain separation

Enums encode as typed values, not bare names.

Example canonical tree:

```json
{"$enum":"ActionType","name":"CODE_EDIT"}
```

Dataclasses use a stable registry type name.

Boolean map keys are rejected. Map entries are sorted by canonical key bytes, not `str(key)`.

Add vectors for enums, bytes, dataclasses, nested maps, big integers, Unicode normalization, invalid path forms, and invalid numeric domains.

## ERR-018 - Quiescence ordering

Every normal and expiry path uses exactly:

```text
stop/cancel
-> prove OS quiescence
-> capture_after
-> finalize observation
```

`capture_after` before quiescence is non-conformant.

## ERR-019 - Transition source of truth

Create one machine-readable state machine definition and generate:

- human transition tables
- reducer legality checks
- illegal-transition tests
- event coverage tests

Every EventType must have a reducer case. Every state-bearing type must have a transition policy or explicit immutable-only semantics.
