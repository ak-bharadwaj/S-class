## 4. Deep-Dive on Hunk 7 Discrepancy & Resolution

### Declaration Claim
`KERNEL-CHANGES.md` Hunk 7 asserts:
> "Removal of MagicMock Name Checks in `WorkerContract.execute` (lines 1970–1988). Remove all `type(...).__name__ != 'MagicMock'` backdoors from kernel. Enforce that `request` must be `AuthorizedWorkRequest` and `boundary` must be `BoundaryContext`. Explicitly reject any object whose class is named `'MagicMock'`."

### Verification Evidence
Inspection of `20-RUNTIME/sclass_runtime_v6_0_1.py` reveals that while the legacy backdoor allowlist (`and type(request).__name__ != "MagicMock"`) was removed, the string check `type(...).__name__ == "MagicMock"` was **NOT eliminated**. Instead, it was retained as an explicit fail-closed guard:

```python
# 20-RUNTIME/sclass_runtime_v6_0_1.py:2241-2252
if not isinstance(request, AuthorizedWorkRequest) or type(request).__name__ == "MagicMock":
    raise PermissionError("WorkerContract.execute accepts only AuthorizedWorkRequest; WorkProposal/WorkNode execution is prohibited")
if boundary is None or not isinstance(boundary, BoundaryContext) or type(boundary).__name__ == "MagicMock":
    raise PermissionError("WorkerContract.execute requires an authentic BoundaryContext; direct execution outside ExecutionGate is prohibited")
...
if _gate_capability is None or _gate_capability is not getattr(self._boundary, "_gate_capability", None) or type(self._boundary).__name__ == "MagicMock":
    raise PermissionError("WorkerContract.execute cannot be invoked outside ExecutionGate; gate capability missing or invalid")
```

The identical check is also present in `src/sclass/workers/harness.py:92, 99`.

### Audit Finding
Classified as **DISCREPANCY / NON-MATCH** with respect to the declaration's title ("Removal of MagicMock Name Checks"). The string check remains active. However, its security direction is **TIGHTENS_FAIL_CLOSED**, because it actively denies execution to any object named `MagicMock` rather than bypassing security invariants.

## 5. Security Direction Audit & Loosening Changes

Every hunk was classified by its security impact:
- **TIGHTENS_FAIL_CLOSED:** Enforces stricter validation, eliminates fallbacks, prevents bypasses.
- **NEUTRAL:** Architectural refactoring, test hooks, or cross-platform compatibility without security degradation.
- **CAN_LOOSEN_SKIP:** Changes that relax previous validation checks.

### Critical Audit Findings: Two Loosening Changes Identified

#### Finding 1: Conformance Schema Version Relaxation (`SEM-H07`)
- **Location:** `10-CONFORMANCE/sclass_semantics_v6_0_1.py:5372`
- **Baseline Code:**
  ```python
  elif int(row[0]) != self.STORE_SCHEMA_VERSION:
      raise ValueError(f"unsupported SQLiteEventStore schema version: {row[0]}")
  ```
- **Integration Code (`f28fb942`):**
  ```python
  elif int(row[0]) > self.STORE_SCHEMA_VERSION:
      raise ValueError(f"unsupported SQLiteEventStore schema version: {row[0]}")
  ```
- **Security Implication:** **FORWARD-COMPATIBILITY RELAXATION / LOOSENING**. Relaxes strict invariant checking by accepting database instances created with older schema versions (`row[0] < self.STORE_SCHEMA_VERSION`) without raising an error and without executing an automatic migration. If the runtime assumes newer schema columns exist, operations will encounter unhandled SQLite exceptions rather than failing closed at connection time.

#### Finding 2: Runtime Non-Linux Platform Fallback (`RUN-H02`)
- **Location:** `20-RUNTIME/sclass_runtime_v6_0_1.py:25-33`
- **Baseline Code:**
  ```python
  import resource  # Top-level unconditional import (fails closed on non-Linux hosts)
  ```
- **Integration Code (`f28fb942`):**
  ```python
  try:
      import resource
  except ImportError:
      class MockResource:
          RLIMIT_CPU = 0
          RLIMIT_AS = 1
          RLIMIT_NPROC = 2
          RLIMIT_FSIZE = 3
          def setrlimit(self, res, limits): pass
      resource = MockResource()
  ```
- **Security Implication:** **PLATFORM ENFORCEMENT RELAXATION / CONDITIONAL LOOSENING**. On non-Linux environments where `resource` is unavailable, `setrlimit()` becomes a silent no-op. Untrusted worker processes executed on non-Linux hosts will not be constrained by OS-enforced memory (`RLIMIT_AS`) or CPU limits, relying solely on cooperative containment.
