## Non-substitution rules

- Bubblewrap, AppArmor, Landlock and cgroups have different responsibilities. Do not mark one as an equivalent fallback merely because it exists on the host.
- If the required isolation cannot be established, fail closed: do not start the worker and record BLOCKED. Do not downgrade to best-effort and describe it as prevention.
- Detection logs, workspace diffs, telemetry and later containment are not prevention evidence.
- No tool output is canonical state or release authority. The kernel remains the owner of state, evidence admission and release.


## R9 explicit host-OS fail-closed rule

No source-backed platform tool facts or completed adversarial outputs were available in R9. bubblewrap, AppArmor, Landlock and cgroups are complementary Linux candidates only; each effective control must be observed and negative-tested on the exact target host. Do not infer prevention from package presence, a configuration file, or a successful startup. macOS, Windows and IDE-hosted host-native execution have no prevention claim in this plan: **host-native = detect + contain, and result BLOCKED** whenever the task requires prevention that is not proven. No fallback runtime, container or protocol SDK may bypass ExecutionGate or create a second durable store.
