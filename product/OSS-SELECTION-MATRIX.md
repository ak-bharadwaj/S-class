# OSS Selection Matrix — R9 (full prior sweep retained; qualification not implied)

Prior-sweep corpus retained and extended for R9. This is a research shortlist, not an adoption approval. Frozen v6.0.1 remains authoritative; no kernel event, enum, or state-machine changes are proposed here.

## Scoring policy

Every capability class is crossed with every lifecycle phase P0–P11 using the frozen phase labels. Each cell lists at least three candidates plus build-own. Score dimensions are age, release cadence, last release date, maintainer breadth, adoption (dependents/downloads), license, security record (advisories), API stability, and pinned/hash-installed adapter capability. `UNVERIFIED` means no primary-source evidence was captured for that exact metric in this sweep; it is not a neutral score and must not be read as good. Numeric claims are omitted unless verified from a primary source. Retrieved date is recorded per candidate below. No tool may become foundational while required fields remain UNVERIFIED.

**Build-own default:** not recommended. It is included as a comparison option, not permission to rebuild the do-not-build list. Build only a narrow S-Class adapter or missing policy glue; never build an agent loop, IDE, generic parser/indexer, generic protocol implementation, test runner, fuzzer, container runtime, workflow engine, telemetry platform, or generic RAG framework.

## Capability decisions

| Capability class | Provisional selection | Reject / defer rationale |
|---|---|---|
| agent runtime | Host IDE runtime launched through ExecutionGate; OpenHands, mini-SWE-agent, smolagents and LangGraph are optional adapters only | Do not embed an agent loop: SDK age/API, host isolation and write-scope proof are unavailable. Young/pre-1.0 SDKs remain optional; without a proven ExecutionGate boundary, do not launch. |
| protocol | MCP Python SDK or ACP SDK only when required by the host, via replaceable adapters | SDK maturity/API stability is not the same as protocol adoption. MCP 2.x API stability and ACP transport/result contracts require exact compatibility tests; neither may own canonical tools or lifecycle state. |
| spec/requirements | JSON Schema for structure; OpenAPI for API contracts; Spec Kit/OpenSpec as L1 content | Pydantic is deferred as sole wire-schema authority until model/schema conversion equivalence is demonstrated; CUE is deferred because it introduces a new schema language/translation boundary; process sources stay content-only to avoid duplicate workflow state. |
| parsing/index | Tree-sitter, SCIP and ast-grep as bounded repo-intelligence candidates | Tree-sitter/SCIP source facts are absent and coverage may be partial; SCIP needs an independently qualified indexer and freshness manifest; ast-grep patterns can miss semantic relationships and must remain proposed-delta inputs. |
| static analysis & security | Semgrep plus Bandit as complementary bounded scanners | Semgrep rules must be assessed separately from the engine and their license/scope is UNVERIFIED; Bandit is Python-scoped and cannot replace multi-language analysis; CodeQL CLI is deferred until permitted license/host integration and output-contract evidence are available. |
| dependency/SBOM/license/secret scanning | pip-audit plus OSV-Scanner, Syft and cyclonedx-bom; Gitleaks for secrets | pip-audit is Python dependency-scoped; OSV-Scanner database/source freshness and native digest are UNVERIFIED; Syft and cyclonedx-bom differ in inventory scope, so require independent inventory reconciliation rather than treating either as complete. |
| provenance/signing | Cosign verification against explicitly bound trust roots; repository-native provenance where available | Cosign binary/trust policy and release evidence are UNVERIFIED; provenance generator scope varies by CI host, and signature validity alone cannot establish release approval. |
| test runner | pytest for Python test collections; unittest only as a documented fallback | unittest is deferred as sole adapter because discovery/reporting semantics differ and need their own F10 contract; Tavern is narrower (API/YAML-oriented) and is not a general repository test runner. |
| property/API/env testing | Hypothesis and Schemathesis as separate property/API adapters | Hypothesis has a specified MPL-2.0 file-level review issue; Schemathesis covers API-schema contracts rather than all domain properties; Atheris is coverage-guided fuzzing with a distinct input/oracle contract and is not a substitute for property strategies. |
| mutation testing | mutmut optional diagnostic for Python | Mutation scores are not proof; Cosmic Ray would add overlapping Python mutation mechanics; Stryker targets other ecosystems and cannot be the Python default without project-specific applicability. Keep all mutation findings advisory until F10 evidence exists. |
| coverage | coverage.py for Python; llvm-cov/gcovr only for matching compiled targets | coverage.py line/branch counters describe executed Python code only; llvm-cov depends on LLVM instrumentation and is mismatched to Python-only projects; gcovr is relevant to gcov-style compiled coverage, not a drop-in Python substitute. |
| policy engine | OPA only for fixed, non-authoritative policy fixtures | OPA facts and policy bundle identity are UNVERIFIED and its result has no direct authority; Cedar and Casbin have different policy-language/integration surfaces and are deferred until semantic equivalence and adapter output are tested. Do not build a policy/workflow engine. |
| sandbox/isolation per OS | Linux candidate: bubblewrap plus policy-specific AppArmor/Landlock/cgroups controls | bubblewrap alone does not prove syscall, network, credential or resource confinement; nsjail and Firejail are deferred until escape-suite and policy-equivalence results exist. macOS/Windows/IDE-hosted prevention is not claimed; unsupported required boundary => BLOCKED and no launch. |
| workflow/CI | Existing repository-native workflow; CI tools remain external orchestration | GitHub Actions is only relevant in GitHub-hosted repos; GitLab/Buildkite introduce different trust/runner models and are not selected without the actual host; no external CI can become a second lifecycle engine or state store. |
| observability | OpenTelemetry Python as optional instrumentation; Prometheus/Grafana only if already operated | OTel core and every contrib/exporter package need separate source/license/data-egress checks; Prometheus metrics alone do not provide trace context; OpenCensus adds migration/API overlap and is deferred until an explicit requirement exists. |

Any candidate proven to be younger than two years or pre-1.0 at qualification time is content-source or optional only, never foundational. ## Selection rationale and hard rejection rules

- **Most mature proven first means evidence-first, not star-count-first.** A candidate with unknown release history, security record, license, API stability, or pinning support cannot be marked qualified even if its ecosystem is popular.
- **No candidate is currently qualified by this document.** The choices above are preferred candidates for qualification, not final deployed dependencies.
- **Build-own** is reserved for narrow S-Class-specific adapters, policy mapping, digest binding, and output normalization. It is rejected for generic tooling covered by mature upstream projects or prohibited by the frozen OSS do-not-build list.
- **Security scanners:** a clean scan is a tool result, not proof of no vulnerabilities; bind database snapshot, scanner version, config, target digest, exit status, and raw output.
- **Parsing/indexing:** bind source snapshot, parser/grammar version, indexer version, and completeness. Missing/unresolved references are MISSING, not PASS.
- **Testing:** bind the entire test input set, environment digest, runner/plugin/config and result. Agent-authored claims do not become evidence without a qualified adapter.
- **Sandbox:** prevention claims are limited to S-Class-launched workers inside the qualified boundary. Host-native IDE tools are detect-and-contain only.
- **Workflow/observability:** external CI and telemetry are not a second authority and cannot create canonical lifecycle state.
