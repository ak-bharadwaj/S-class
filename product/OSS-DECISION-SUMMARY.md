## Applied adoption-level rule

L2 may be proposed only where the allowed JSONL supports age >=2 years, version >=1.0, a permissive license and a recent *actual upstream release*, each with `source_url` and `retrieved_at`, followed by exact hash-locked installation, advisory/license review, API/boundary and F10 qualification. L3 requires a separately justified, narrowly bounded runtime substrate plus host-specific prevention proof. L4 is not proposed. No evidence-based level promotion is made in R9 because the facts feed is missing. The named young/pre-1.0 SDKs remain optional L1/L2 adapters and never foundational. `release_files_last_12mo` is an upload-file count, not release cadence.

## Non-negotiable authority and status boundary

The kernel alone owns canonical state, authorization, budgets, evidence identity/freshness/independence, closure and release readiness. Every external tool output remains an untrusted claim or identity-bound observation admitted only by existing F10/kernel policy. No tool can add a kernel event/enum/state transition, build a second durable store, close a gate by self-report, or authorize release. No tool is qualified and no `ACCEPTED` status is added.
